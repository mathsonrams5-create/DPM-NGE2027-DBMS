Security & Safeguards

Configuration this system is designed around, mapped to the three risk areas raised for this project.

1. Data Privacy

Compliance with public service and electoral law. Only fields required for verification are collected; a retention/disposal rule removes candidate data no longer needed after NGE 2027 in line with DPM records policy.

2. Unauthorized Access

Role-based sign-in (Administrator / Data Entry / Verifying / Viewer) is enforced at login. In production this is backed by two-factor authentication (2FA) and encryption of data at rest and in transit.

3. System Reliability

Records save automatically as you work. A production deployment adds scheduled backups, a tested disaster-recovery restore procedure, and an offline export as fallback.

About This Prototype

What this file is, what it already does, and what turning it into a real production system for DPM still requires.

What this is

A self-contained web app built to the same visual system as the DRBMS prototype, implementing the Data Entry Matrix (Agency Heads Register, Public Servants Register) and the Step-by-Step Framework already approved for this project. When published as a Claude artifact it is backed by a real shared, persistent data store — everyone who opens this link sees the same live register, the same audit log and the same committee feedback, and records survive between visits. That is the "backend" this prototype now runs on.

What kind of backend this is — and isn't

This is Claude's built-in artifact storage, not the department's own database. It is genuinely shared and persistent, which makes it good for this stage — committee review, layout and workflow feedback. It is not yet the production system described in the DBMS proposal:

  • Data lives inside Claude's platform, not on a DPM-owned or DPM-approved server — EM MIS should confirm whether that is acceptable for public-service resignation records even at review stage.
  • The published link is public and unauthenticated by default — anyone with the URL can open it. There is no password, no expiry, and no way to restrict it to committee members only, unless DPM's Claude plan is Team/Enterprise (which allows organization-only sharing instead of a public link).
  • Sign-in on this page is a role-selector for demonstration, not real authentication — it does not enforce 2FA or verify identity.
  • Moving to production still means what Section 5–7 of the DBMS proposal covers: a Vertabelo/DbSchema-modelled database on a DPM-approved host, real authentication with 2FA, and the HRIS/PNGEC integrations.
Data in this version

The two seeded entries are clearly-labelled sample data, not real officers' records — real names, phone numbers and emails have been left out of this shareable version deliberately, since the link is public. Once EM MIS confirms hosting and access control, real entries can be loaded before this goes into operational use.
